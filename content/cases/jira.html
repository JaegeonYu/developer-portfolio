1문의 1답변 구조를 대화형으로 바꾸고 Jira와 연동

emroCloud · 전체 고객사가 사용하는 고객문의 기능

JavaSpringOracleJira REST APIAWS S3데이터 모델링

답변 한 칸, 재요청 한 칸뿐이던 문의 구조를 대화처럼 이력이 쌓이는 구조로 바꾸고, 이미지를 넣을 수 있는 에디터와 함께 첨부파일·이미지까지 담당자의 Jira로 그대로 전달되도록 연동했습니다.

문제 상황

고객사가 서비스 문의를 남기면 담당자가 답변하고, 고객은 필요하면 재요청하는 기능입니다. 기존 구조는 문의 한 건에 답변 한 칸, 재요청 한 칸만 있었습니다. 그래서 주고받는 대화가 길어지면 기록할 곳이 없었고, 상태도 마지막 것 하나만 남았습니다. 예를 들어 처음 요청은 처리 완료됐고 재요청만 반려됐는데, 화면에는 문의 전체가 '반려'로 보여 실제 진행 상황을 알기 어려웠습니다.

담당자는 문의를 Jira에서 처리하는데, 문의 내용은 텍스트만 입력할 수 있었고 첨부파일도 Jira로 넘어가지 않았습니다.

AS-IS

문의 한 건이 답변과 재요청을 한 칸씩만 가지고, 상태는 마지막 하나만 남습니다.

내가 바꾼 점

구조 개선과 데이터 이관

요청과 진행 이력을 분리한 구조로 바꾸고, 기존 문의를 상태별 기준을 정해 이관했습니다. 작성 중이거나 아직 접수되지 않은 문의는 요청 정보만 옮기고, 접수 이후 단계까지 진행된 문의는 마지막 상태를 첫 진행 이력으로 함께 옮겼습니다.

Jira 첨부파일 연동

문의 본문과 댓글에 붙은 파일을 Jira 이슈와 댓글에 함께 등록했습니다. Jira는 같은 이름의 파일을 다시 올리면 이름을 자동으로 바꿔 댓글의 파일 링크가 엉뚱한 파일을 가리킬 수 있었습니다. 그래서 저장할 때 파일명에 시각을 붙여 고유하게 만들고, 링크를 깨뜨리는 특수문자는 정리했습니다.

에디터 도입과 이미지 저장 방식 변경

텍스트만 입력하던 문의에 이미지를 넣을 수 있는 에디터를 적용했습니다. 처음에는 이미지를 글 안에 긴 문자열(Base64)로 넣는 에디터 기본 방식을 썼는데, 이미지가 들어간 문의는 Jira의 본문 길이 제한을 넘어 연동이 실패했습니다. 그래서 이미지를 S3에 저장하고 본문에는 짧은 주소만 남기도록 바꿨습니다. Jira로 보낼 때는 이 주소의 이미지를 첨부파일로 올리고 본문에서 해당 이미지를 표시하도록 변환해, 이미지가 포함된 문의도 연동됩니다.

본문 이미지를 Jira로 전달하는 흐름

에디터에 이미지 첨부 → S3 저장본문에는 짧은 이미지 주소만 저장
↓
Jira 전송 시 이미지 주소 추출S3에서 내려받아 고유 파일명으로 첨부
↓
Jira 이슈·댓글 본문에 이미지 표시본문 길이 제한 초과 해소
담당자가 놓치지 않도록

고객이 댓글을 남긴 문의를 담당자가 바로 알아볼 수 있도록, 목록을 '요청·재요청 상태 → 아직 확인하지 않은 댓글 → 긴급 여부' 순으로 우선 표시했습니다. 완료 요청 후 7일이 지나도록 처리되지 않은 문의는 스케줄러로 자동 완료해 처리 누락으로 쌓이는 문의를 줄였습니다.

결과

emroCloud 전체 고객사의 기존 문의를 새 구조로 이관했습니다. 문의마다 주고받은 내용과 상태가 이력으로 남아 진행 상황을 정확히 볼 수 있고, 첨부파일과 이미지가 포함된 문의도 담당자의 Jira에 그대로 전달됩니다.
