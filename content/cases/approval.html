중복 요청의 경합 지점 제어

일괄결재 · 입찰 제출

일괄결재 재요청

문제 상황 선행 트랜잭션이 끝나기 전에 같은 결재가 재요청되어 업무 데이터의 정합성이 어긋났습니다.

AS-IS

처리 중인 결재를 구분하지 못해 동일 건의 업무 모듈이 중복 실행됐습니다.

TO-BE

시작 시 처리중·완료 건을 제외하고 처리중 상태를 기록했습니다. 건별 신규 트랜잭션에서 전처리 후, 처리중인 건만 완료로 갱신했습니다.

판단과 해결 요청 시점의 결재 상태를 제어 기준으로 삼고, 시작 상태 기록과 건별 처리의 트랜잭션을 분리했습니다.

입찰 중복 제출

문제 상황 제출 여부 검사 후에도 미커밋 상태의 재요청으로 중복 데이터가 생성돼 조회 오류가 발생했습니다.

AS-IS

여러 서버에서 검사와 저장이 동시에 진행되어 선행 제출을 확인하지 못했습니다.

TO-BE

입찰 ID 행을 SELECT … FOR UPDATE로 잠근 뒤 기존 제출 여부 검사와 저장을 수행했습니다.

판단과 해결 여러 서버가 공유하는 DB를 제어 지점으로 선택했습니다. 같은 입찰의 제출은 잠금 뒤 순서대로 검증하도록 했습니다.
