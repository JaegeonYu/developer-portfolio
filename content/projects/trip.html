이메일 인증 응답 개선

SMTP 통신으로 지연되던 이메일 인증 요청을 멀티스레드 기반 비동기 처리로 변경했습니다. 인증 요청의 응답 시간이 3초 이상에서 0.5초 미만으로 줄었습니다.

요청 순서를 시각화해 협업

API 명세서만으로 맞추기 어려웠던 처리 순서를 지역 팔로우·회원가입·로그인 시퀀스 다이어그램으로 정리해 GitHub에 공유했습니다. 프론트엔드 팀원과 구현 방향을 확인하고 피드백을 주고받는 기준으로 사용했습니다.

SSE 알림 흐름과 연결 관리

서버에서 클라이언트로 보내는 단방향 알림이 필요해, 주기적으로 확인하는 Polling 대신 Spring의 SseEmitter로 연결을 유지하는 SSE를 선택했습니다.

  1. 사용자가 관심 지역을 팔로우합니다.
  2. 관리자가 해당 지역에 콘텐츠를 추가하면 팔로워의 알림을 DB에 저장합니다.
  3. 접속자에게는 SSE로 알림 ID를 보내고 클라이언트가 상세 내용을 조회합니다.
  4. 미접속자의 알림은 로그인 후 SSE 연결 시 미읽음 알림으로 전달합니다.

사용자별 연결은 ConcurrentHashMap에 보관하고 종료·시간 초과 콜백에서 정리했습니다. 연결 저장소가 단일 서버 메모리에 있으므로 다중 서버로 확장하려면 Redis Pub/Sub 같은 메시지 전달 계층이 필요하다는 한계도 확인했습니다.

SQL 호출과 조회 범위 개선

  • 알림 생성은 팔로워 조회 후 건별 INSERT하던 1+N회 호출을 INSERT INTO … SELECT 한 문장으로 합쳤습니다. 선택한 알림의 읽음 처리는 foreach와 IN 조건으로 묶었습니다.
  • 사용자와 여러 권한의 관계를 MyBatis 결과 매핑으로 표현했습니다.
  • 관광지 추천은 전체 결과를 애플리케이션에서 자르는 대신, 리뷰 수를 구하는 상관 서브쿼리와 평점 정렬·LIMIT을 SQL 안에서 처리했습니다.
