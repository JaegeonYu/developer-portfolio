같은 요청이 두 번 처리되던 문제를
상태값과 DB 잠금으로 해결했습니다.

여러 건을 한 번에 결재하는 일괄결재는 결재상태로 이미 처리 중인 건을 건너뛰게 하고, 입찰 제출은 DB 행 잠금으로 순서를 보장해 연 10~20건이던 중복 제출을 재발 0건으로 막았습니다.

낙관적 방식 선점 · 비관적 동시성 제어동시성 제어 사례 읽기 ↗ 실무 · 데이터 관계 / 정합성

복사 오류의 원인을
데이터 관계에서 찾아 해결했습니다.

화면 오류처럼 보이던 문제가 하나로 이어져야 할 데이터가 여러 갈래(1:N)로 나뉜 탓임을 확인했습니다. 고객사 담당자와 실제 사용 방식을 확인해 6개 고객사의 데이터를 보정하고 서버 검증을 추가했습니다.

1:N 관계 정리 · 서버 검증복사 오류 사례 읽기 ↗ 실무 · 대량 데이터 / 운영 DB

7년 치 로그 약 2억 건을
나눠 삭제하는 방식으로 정리했습니다.

한 번에 지우면 복구용 변경 기록이 저장 공간을 채워 운영 DB가 멈출 위험이 있었습니다. ROWID 기반 분할 삭제로 바꾸고 스케줄러로 자동화해 운영팀에 인수인계했습니다.
