요구사항부터 운영까지 맥락을 이어갑니다.

요청된 기능을 구현하기에 앞서, 현업이 어떤 업무를 수행하고 기존 방식에서 무엇이 불편했는지 파악하려고 합니다. 화면이나 기능 목록만 보는 대신, 사용자가 판단하는 기준과 그 판단에 필요한 데이터가 어디서 만들어지고 어떻게 이어지는지 함께 살핍니다.

현대모비스 원가재료비 관리에서는 Excel로 관리하던 계산을 시스템으로 옮기며 구매원가팀과 환율·관리비·단가 등 업무 요건을 검증했습니다. 계산 결과가 다를 때도 시스템 오류로만 보지 않고, 현업 계산식과 반영된 원가 요소를 대조해 누락 원인을 확인했습니다.

고객문의 개선에서는 기존의 1문의 1답변 구조가 실제 대화형 진행 이력을 담기 어렵다는 점에서 출발했습니다. 요청과 진행 이력을 나누고 Jira 연동의 첨부파일·콘텐츠 제약까지 함께 다루며, 업무 흐름에 맞는 데이터 구조와 처리 방식을 고민했습니다.

운영 중 발생한 중복 결재와 입찰 제출 역시 재요청 자체보다, 요청이 도착한 시점의 처리 상태와 트랜잭션 완료 여부를 살펴 개선했습니다. 이렇게 실무에서 마주한 고민을 체계화하기 위해 데이터 모델링과 SQL 튜닝을 학습하며, 업무의 맥락과 데이터 정합성을 함께 이해하는 개발자로 성장하고자 합니다.

Java · Spring Oracle · DB2 · SQL 업무 이해 · 데이터 정합성 · 서비스 운영
