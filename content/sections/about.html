업무를 이해하고, 데이터로 풀어갑니다.

B2B 서비스를 개발·운영하며 업무의 맥락을 데이터 구조와 처리 방식에 연결하는 것을 중요하게 생각합니다. 저연차였지만 프로젝트와 기능 개선을 맡을 때 개발만 하지 않았습니다. 고객사 현업 담당자와는 요구사항의 배경과 업무 흐름을 확인했고, 고객사 IT 담당자와는 개발 환경 구성부터 ERP에서 데이터를 어떻게 관리하는지, 인터페이스로 저희 서비스와 어떻게 동기화되는지까지 직접 소통하며 맞춰 나갔습니다. 구매요청 복사 기능을 개선할 때도 고객사 ERP의 관리 방식을 확인한 뒤 중복 데이터를 정리했습니다.

데이터를 다룰 때는 결과뿐 아니라 DB 안에서 어떻게 동작하는지도 함께 봅니다. 대량 삭제에서는 변경 기록이 쌓이는 방식을 고려해 나눠 지우는 방법을 택했고, 중복 요청은 DB 행 잠금으로 처리 순서를 보장해 막았습니다.

이러한 실무의 고민을 체계화하기 위해 데이터 모델링과 SQL 튜닝을 꾸준히 학습하고 SQLP를 취득했습니다. 익힌 실행계획·인덱스 관점은 지금 프로젝트에서 새로 작성하는 SQL에 적용해, 조건에 쓰는 컬럼의 선택도를 고려하며 나중에 튜닝할 필요가 없는 SQL을 작성하고 있습니다. 앞으로도 개발 경험을 바탕으로 업무와 데이터를 함께 이해하고, 현재 시스템에서 개선할 지점을 지속적으로 찾아가는 개발자가 되고자 합니다.

AI는 프레임워크가 아닌 라이브러리처럼 씁니다.

프레임워크는 정해진 흐름 안에 제 코드를 끼워 넣는 방식이고, 라이브러리는 제가 흐름을 잡고 필요한 기능만 가져다 쓰는 방식입니다. 저는 AI를 라이브러리처럼 씁니다. 무엇을 만들지, 결과가 맞는지는 제가 판단하고 AI는 필요한 순간에 불러 씁니다. SQLP 스터디 운영 시스템도 AI와 함께 빠르게 만들었지만, 변경 사항을 자동으로 검사하는 테스트와 공개하면 안 되는 정보가 외부에 노출되지 않도록 막는 검사 단계를 두었습니다.

빠르게 결과를 내야 하는 일은 AI에 맡겨 속도를 내고, SQL 튜닝처럼 깊이 이해해야 하는 분야는 직접 공부하며 기본기를 쌓고 있습니다. AI를 잘 활용한다는 것은 AI가 내놓은 답이 맞는지 판단할 수 있다는 뜻이라고 생각합니다.
